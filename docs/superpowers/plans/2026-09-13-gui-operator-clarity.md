# GUI：讓畫面說清楚「這是什麼、現在能做什麼」

2026-09-13 起草。**提案，尚未執行。** 來源是一輪 read-only 的介面評估
（Codex / gpt-6-astra），加上我自己對其中兩條的親自查證。

**這不是重新設計。** 評估的結論是五區切法（首頁／調查／規則／報表／系統）應該
保留，真正的問題集中在三件事：資料新鮮度沒有時間依據、把「查得到的動作」呈現成
「建議的處置」、以及相鄰工具的互動規則不一致。**沒有一條要求恢復已刻意移除的
東西**（inbox、stepper、JSON preview、首頁重印告警清單）。

## 已親自查證的兩條（不是轉述）

### V1. 流量結果下方的排行榜跑的是別的查詢

`src/static/js/v2/areas/cards.mjs:773`：

```js
return api.post("/api/dashboard/top10",
  Object.assign({}, queries[0], { mins: 1440 }));
```

`queries[0]` 是**第一個儲存查詢**，`mins` 寫死 **1440**。它被接在流量搜尋結果的
正下方，而上面那個搜尋可能是「某個 app、最近一小時」。版面上兩者看起來是同一件
事的兩種呈現，實際上條件完全不同。

### V2.「執行歷史」這個標題承諾的，正是它自己的說明否認的

`src/i18n_zh_TW.json`：

- `gui_au_rep_history` = 「執行歷史」
- `gui_au_rep_hist_note` = 「這裡顯示的是這個排程目前的狀態，**不是一份逐次執行的歷史**」

而那句說明要展開才看得到。有人來找「上次到底跑了沒」的證據時，最不該藏起來的就是
這個限制。

## 建議的執行順序

分三批，每批各自可交付、可驗收。**先做便宜且會誤導人的，再做結構性的。**

### 批次 1：誤導性標示 —— 2026-09-13 已完成

- V1：排行榜標出查詢名稱、期間、並明說「獨立於上方搜尋」；預設收合。
- V2：`gui_au_rep_history` 改名「最近一次執行」，並把限制從展開說明搬到標題旁。
- R8：失敗與空結果只給一個結論。畫面狀態收斂成五種：尚未查詢／查詢中／成功但零筆／
  查詢失敗／結果不完整或過期。

**驗收**：真機各走一次，截圖比對；守門測試斷言「同一個容器不得同時出現失敗訊息與
空結果說明」。

### 批次 2：資料新鮮度 —— R1 於 2026-09-13 完成，R7 未做

- R1：健康摘要與告警計數旁顯示「資料截至 HH:MM」，提供局部更新；超過該來源合理
  更新週期時明示「資料已過期」並保留最後已知值。
- R7 的後半：「已儲存」與「已套用」分開，不要讓成功 toast 承擔兩種意思。

**為什麼這批單獨一批**：它要動的是 `api.mjs` 的快取語意如何呈現，會影響所有讀那
份快取的畫面。**這批的驗收必須包含「拔掉網路之後畫面說什麼」**——這正是 R1 在講
的情境，而它抓不到就等於沒做。

### 批次 3：結構性（要先寫 spec）

- R2：動作清單改成「先看／再改」的順序，並把「事發當時 vs 現在的政策」與取樣上限
  說出來。
- R3：結果上方常駐一行「已執行的條件」，有修改時顯示「條件已變更，尚未查詢」；
  跨頁返回保留查詢、分頁與選取。
- R4：報表區保留「進行中／最近完成」工作列，跨頁有提示，返回可接回進度。
- R5、R6：告警清單的找回能力；首頁主動作與 KPI 連結帶範圍。

這四條各自改變操作者的心智模型，不是換文案。**寫 spec 再動手。**

## 刻意不做

評估明確支持保留、這份計畫也不動的：五區頂層切法、不重建 inbox、首頁不重印告警
清單、table 排序歸 area 管（它只拿得到當頁資料）、glossary 詞彙不譯、不恢復
JSON request preview、不恢復 stepper。

`investigate.mjs`（139 KB）與 `system.mjs`（144 KB）的大小本身不是拆分的理由——
評估的判斷是 investigate 的三個搜尋工具確實是同一件事（`one instrument: a query
workbench`），真正混進去的是儲存排行的管理，而那正是 V1。

## 未做的驗證

這輪評估**沒有實際開瀏覽器**，所以擁擠、對比、可讀性都還沒有視覺證據。批次 1 與 2
的驗收必須包含真機走查——這個 repo 記過的教訓是，全套綠與閘門綠都抓不到「打開它
來看的人」才會看到的東西。

## 批次 1 執行結果（2026-09-13）

三項都做了，各自注入驗證會變紅。45 支相關 e2e 全綠、i18n 十類 0。

- **R8**：`state.phase` 只有 `idle`/`busy`/`done`，**沒有 `error`**。失敗落在

  「快取有在收嗎／視窗夠嗎」——全都在回答一個沒被問出口的問題。失敗現在有自己
  的面板。**流量頁的錯誤存在 `state.meta.error`、其他 view 存 `state.error`**，
  兩個都要收（我第一版只改了後者，等於只修好一半）。
- **V1**：排行榜加常駐說明「跑的是儲存查詢『X』的 24 小時，不跟隨上方的搜尋

- **V2**：「執行歷史」→「最近一次執行」，限制從需要展開的 `disclosure()` 搬到

### 順帶掀出的事

`test_filter_pill_reaches_query_and_kpis_update` 的註解寫
`the empty result explains itself`、斷言三條「為什麼是空的」診斷——**但 e2e 把

## 批次 2 / R1 執行結果（2026-09-13）

健康卡現在說「資料截至 HH:MM」，超過 10 分鐘（測試機 monitor 的輪詢間隔）就加
註「已過期，畫面沒有自動更新」。

**關鍵設計：時間取自 `api` 快取記下的「抓取時刻」，不是渲染時刻。** 用渲染時間
會永遠顯示「剛剛」——那比不顯示更糟，因為它看起來像在保證新鮮。
`core/api.mjs` 新增 `fetchedAtMs` map 與 `api.fetchedAt(id, params)`，
`reload()` 會一併清掉。

三支守門，各自注入驗證會紅：
- 健康卡有「資料截至」
- **切走再回來（快取命中、畫面重畫）時抓取時刻不得改變**——這支守的正是
  「用渲染時間冒充資料時間」那個唯一會靜默壞掉的方式
- 一小時前的資料要被標成 `data-stale="true"`

**R7 後半（「已儲存」vs「已套用」）未做**，留在批次 2。

## 批次 2 / R7 後半執行結果（2026-09-14）

儲存成功的 toast 從「已儲存 N 項變更。」改成「已儲存 N 項變更。尚未確認套用到
執行中的服務。」

**為什麼不能用「需要重啟」代替**：後端 `gui/settings_helpers.py` **硬編**
`requires_restart: true`——沒有逐欄位的重啟偵測，系統自己也不知道這次改動需不
需要重啟。而那個重啟橫幅只掛在 cache 頁（SY-03），`saveAll` 卻是所有設定頁
（settings / cache / SIEM / TLS / security ×3）共用的。所以能誠實說出口的只有
「已儲存」與「尚未確認套用」這兩件事。

**守門改過一次**：第一版斷言 `system.mjs` 的原始碼裡有那個 i18n 鍵——那是代理
指標，一次死碼或一次 `t()` 拼錯都能讓它繼續綠。改成**驅動一次真的存檔並讀渲染
出來的 toast 文字**，注入時的失敗訊息直接印出 `'Saved 1 change(s).'`。

（同一種病這個 repo 記過三次，見 `gate-checks-shape-not-rule`。）

**批次 2 到此完成**（R1 於 2026-09-13，R7 後半於 2026-09-14）。

## 批次 3 五條的逐條查證（2026-09-14）

### R5 不是「缺找回能力」，是**第 26 筆之後在 GUI 裡拿不到**

`areas/alerts.mjs:340` `mountList`：

```js
function params() {
  return { status: state.status, type: state.type,
           page: state.page + 1, page_size: 25 };
}
```

- `state.page` 全檔只出現兩次：`params()` 讀它，以及切換狀態時 `= 0`。
  **沒有任何地方遞增它**，而 `listFoot()`（`components/page.mjs:250`）只是一行
  文字加一個連結，沒有分頁器。
- `state.type` 只在 `mountAlerts` 從 URL query 取得（`:756`），**畫面上沒有任何
  控制項會設定它**。要按類型篩選只能手改網址。

`filters()` 只建了「全部／新／已確認／已完成」那一排。所以告警一旦超過 25 筆，
舊的那些從介面上**不可達**——這不是「找回能力不足」，是資料拿不到。

嚴重度確實只有色條（`tone: sevTone(a.severity)`），沒有文字。

### R2 的「取樣上限沒說出來」是錯的——它有說

`gui_al_flows_foot` = 「顯示前 {shown} 組，共 {total} 組」，常駐在流量表下方
（`:512`）。`EXPLAIN_N` 的上限本來就寫在畫面上。

R2 真正成立的是另外兩半：

1. **動作順序**：`paintActions()`（`:630`）第一個 push 的是「開啟政策 X」，而
   `acts.forEach` 把 index 0 套上 `lead` ＋ `btn primary`。找到涵蓋規則就等於
   把「改規則集」擺成主動作，「去看那個 workload」排在它後面。
2. **事發當時 vs 現在**：`explainFlows()`（`:181`）送 `basis: "active"`——問的是
   **現在**的政策，而告警敘述的是**事發當時**。這一點畫面上沒有任何交代。
