# GUI：讓畫面說清楚「這是什麼、現在能做什麼」

2026-09-13 起草。**提案，尚未執行。** 來源是一輪 read-only 的介面評估
（Codex / gpt-6-astra），加上我自己對其中兩條的親自查證。

**這不是重新設計。** 評估的結論是五區切法（首頁／調查／規則／報表／系統）應該
保留，真正的問題集中在三件事：資料新鮮度沒有時間依據、把「查得到的動作」呈現成
「建議的處置」、以及相鄰工具的互動規則不一致。**沒有一條要求恢復已刻意移除的
東西**（inbox、stepper、JSON preview、首頁重印告警清單）。

## 已親自查證的兩條（不是轉述）

### V1. 流量結果下方的排行榜跑的是別的查詢

`src/static/js/v2/areas/cards.mjs:773`：

```js
return api.post("/api/dashboard/top10",
  Object.assign({}, queries[0], { mins: 1440 }));
```

`queries[0]` 是**第一個儲存查詢**，`mins` 寫死 **1440**。它被接在流量搜尋結果的
正下方，而上面那個搜尋可能是「某個 app、最近一小時」。版面上兩者看起來是同一件
事的兩種呈現，實際上條件完全不同。

### V2.「執行歷史」這個標題承諾的，正是它自己的說明否認的

`src/i18n_zh_TW.json`：

- `gui_au_rep_history` = 「執行歷史」
- `gui_au_rep_hist_note` = 「這裡顯示的是這個排程目前的狀態，**不是一份逐次執行的歷史**」

而那句說明要展開才看得到。有人來找「上次到底跑了沒」的證據時，最不該藏起來的就是
這個限制。

## 建議的執行順序

分三批，每批各自可交付、可驗收。**先做便宜且會誤導人的，再做結構性的。**

### 批次 1：誤導性標示（便宜，已查證）

- V1：排行榜標出查詢名稱、期間、並明說「獨立於上方搜尋」；預設收合。
- V2：`gui_au_rep_history` 改名「最近一次執行」，並把限制從展開說明搬到標題旁。
- R8：失敗與空結果只給一個結論。畫面狀態收斂成五種：尚未查詢／查詢中／成功但零筆／
  查詢失敗／結果不完整或過期。

**驗收**：真機各走一次，截圖比對；守門測試斷言「同一個容器不得同時出現失敗訊息與
空結果說明」。

### 批次 2：資料新鮮度（中等，最高操作效益）

- R1：健康摘要與告警計數旁顯示「資料截至 HH:MM」，提供局部更新；超過該來源合理
  更新週期時明示「資料已過期」並保留最後已知值。
- R7 的後半：「已儲存」與「已套用」分開，不要讓成功 toast 承擔兩種意思。

**為什麼這批單獨一批**：它要動的是 `api.mjs` 的快取語意如何呈現，會影響所有讀那
份快取的畫面。**這批的驗收必須包含「拔掉網路之後畫面說什麼」**——這正是 R1 在講
的情境，而它抓不到就等於沒做。

### 批次 3：結構性（要先寫 spec）

- R2：動作清單改成「先看／再改」的順序，並把「事發當時 vs 現在的政策」與取樣上限
  說出來。
- R3：結果上方常駐一行「已執行的條件」，有修改時顯示「條件已變更，尚未查詢」；
  跨頁返回保留查詢、分頁與選取。
- R4：報表區保留「進行中／最近完成」工作列，跨頁有提示，返回可接回進度。
- R5、R6：告警清單的找回能力；首頁主動作與 KPI 連結帶範圍。

這四條各自改變操作者的心智模型，不是換文案。**寫 spec 再動手。**

## 刻意不做

評估明確支持保留、這份計畫也不動的：五區頂層切法、不重建 inbox、首頁不重印告警
清單、table 排序歸 area 管（它只拿得到當頁資料）、glossary 詞彙不譯、不恢復
JSON request preview、不恢復 stepper。

`investigate.mjs`（139 KB）與 `system.mjs`（144 KB）的大小本身不是拆分的理由——
評估的判斷是 investigate 的三個搜尋工具確實是同一件事（`one instrument: a query
workbench`），真正混進去的是儲存排行的管理，而那正是 V1。
