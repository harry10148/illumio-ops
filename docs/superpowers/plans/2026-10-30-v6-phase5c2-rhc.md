# v6 P5c-2 Rule Hit Count（RHC）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** rule_hit_count 報表：PCE 原生的已生效規則命中次數。產品隨時能回答「RHC 開了沒」，沒開時報表反灰、不能產生也不能排程；地端可在設定頁經 API 開啟（三步、有防護、要確認），SaaS 照實顯示 PCE 拒絕並說明要找 Illumio 支援。

**Architecture:** 選填的「寫入用 key」（`pce.write_api_key`／`write_api_secret`，owner 角色的 service account；同一把日後也給隔離用）；`services/rhc.py` 移植 5.x `rule_hit_count_enablement.py` 與 `api/reports.py`（狀態兩個 GET、三步啟用、`POST /reports` → 輪詢 → 下載 CSV），CSV 用標準庫解析；報表 builder 依 Active Ruleset 補名稱與範圍，區分「有紀錄但 0 次」與「沒有紀錄」，Draft 規則導向 policy_usage。

**Spec:** spec §6.5 RHC 啟用（三步、防護、反灰）、§6.5 key 決定（寫入用 key）、記憶 nfr-saas-readonly-and-rhc-facts（只有 owner 能產報表與開範本；SaaS 不能經 API 改範本）、rule-hit-count-evaluation（5.x 實作與 lab 驗證：日期要完整 ISO 時戳，否則 406）。

## Global Constraints

- 沿用 P5 全部 Global Constraints（截斷揭露、i18n 無死鍵無動態鍵、用語守門、單一讀寫閘門、英文 conventional commits）。
- 寫入用 key 是秘密：加入 `SECRET_FIELDS`、遮罩、絕不寫進 log。沒填時 RHC 狀態檢查用主要 key 讀（讀範本需 admin/owner，被拒時狀態為「無法判定」並說明需要寫入用 key）。
- 啟用動作只在設定頁、使用者確認後執行；任一步失敗即停並回報已完成的步驟；Draft firewall_settings 已有未 Provision 的變更時拒絕；PCE 拒絕（403）照實顯示，SaaS 加說明。
- 報表：未完全開啟 → `availability` 反灰並說明；排程執行時未開啟 → 失敗並寫原因，不產空報表。

## Review Focus

1. 寫入用 key 不出現在 API 回應、log、匯出（`test_write_key_masked`）。
2. SaaS 403：顯示 PCE 拒絕＋需找 Illumio 支援，不顯示成功、不重試（`test_saas_refused_says_support`）。
3. Draft firewall_settings 有他人未 Provision 的變更：拒絕且不寫任何東西（`test_pending_firewall_settings_refused`）。
4. 已 Provision 但期間內沒命中（0 次）與沒有紀錄（期間後才 Provision、或 Draft 規則）分開呈現（`test_zero_vs_no_record`）。
5. lab：開啟狀態下真拉一次原生報表，兩語系頁面檢查。

### Task 1: 寫入用 key 與 client
`settings/schema.py`（PceSettings 加兩欄，預設空字串）、`settings/secrets.py`、`services/context.py`（`pce_write_client()`，沒填時 `PceNotConfigured`）、PCE 連線頁兩個欄位、contracts。測試：`test_write_key_optional_default_empty`、`test_write_key_masked`、`test_write_client_uses_write_key`、`test_write_client_missing_key`。

### Task 2: RHC 服務
`services/rhc.py`：`rhc_status(ctx) -> RhcStatus(state: enabled|partial|disabled|unsupported|unknown, pce_report, ven_scopes, reason_key, detail)`、`enable_rhc(ctx) -> EnableResult(steps_done, error_key, detail)`、`pull_rhc(ctx, start, end) -> RhcPull(rows: list[RhcRow], start, end)`（CSV 欄位別名沿用 5.x）。測試（假 PCE）：狀態五種、啟用三步成功、任一步失敗停止並列已完成步驟、pending 拒絕、SaaS 403 說明、拉取 406 前已帶完整 ISO 時戳、輪詢逾時、下載失敗、CSV 解析（缺欄位、無法解析的 hit 數略過並計數）。

### Task 3: 設定頁與 API
路由 `rhc.status`、`rhc.enable`（POST，需 CSRF 與確認旗標）；報表前置設定頁一節：狀態、缺哪一半、開啟按鈕（確認對話列出三步與「會 Provision firewall_settings」）。測試：路由與 e2e。

### Task 4: rule_hit_count 報表
`ReportType.RULE_HIT_COUNT`（群組 policy）、`availability` 依狀態反灰、builder：怎麼讀這份報表（與 policy_usage 的差別）、有命中（Ruleset、規則、範圍、次數、最後命中）、0 次（已 Provision、期間內沒命中）、沒有紀錄的已生效規則、Draft 待 Provision 的規則（導向 policy_usage）。測試：`test_zero_vs_no_record`、`test_not_enabled_greyed`、`test_scheduled_not_enabled_fails`、`test_pull_failure_fails_report`、`test_zh_tw_builds`。

### Task 5: 驗收、文件
lab 拉一次（兩語系、page_check 0 問題）；閘門；spec／roadmap；Codex 最終審查（prompt 開頭寫明只做審查）。
