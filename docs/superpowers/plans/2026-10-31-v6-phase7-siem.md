# v6 P7 SIEM 轉送 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把 audit 事件、本產品的偵測與告警、選用的「新連線出現」事件轉送到客戶 SIEM（cef／json／syslog_cef／syslog_json／cef_pce／syslog_cef_pce × udp／tcp／tls／hec），附狀態頁、DLQ（檢視、重送、清除、匯出）與 5.x 設定遷移；不轉流量紀錄。

**Architecture:** 每個「目的地 × 來源」一個游標（`siem_cursor`，記到哪個 id），dispatcher 每輪依 id 讀下一批、格式化、送出、前進游標——取代 5.x 每筆 audit 複製一列 dispatch 的佇列表（.106 已累積 22 萬列）。來源四張表都必須是單調不重用 id：`events`（P4 已改 AUTOINCREMENT）、`alerts`（app.sqlite）、`detections`（flows.sqlite）本階段重建為 AUTOINCREMENT；新增 `new_connection_log`（flows.sqlite），在即時收集新增基準列且基準期已滿時寫一列。5.x 的 formatters／transports／mask 搬進 `illumio_ops/siem/` 並帶著行為測試。

**Spec:** §4.1 目標 4、§6.4 輕量表（SIEM 列）、§6.5 SIEM 轉送、§6.6 F12、§7（SIEM 流量來源、切換連續性）、§8 回收表、§9 驗證；路線圖 P7 列。

## Global Constraints

- 三種來源：`audit`（events，origin=ingest）、`findings`（alerts 與 detections）、`new_connections`（選用）；**不轉流量紀錄**；回填列（origin=backfill）不進 SIEM。
- 新連線事件**不帶連線數或位元組**；帶判定、兩端身分（IP、主機名、labels）、port／協定、first_seen；`traffic_pd` 過濾只作用於新連線；port 只收 0 ≤ port < DYNAMIC_FROM（同新連線報表 `_ELIGIBLE`）。
- 輕量模式：audit 與事件型告警照常完整轉送；偵測、流量告警、新連線在輕量模式不會產生——狀態頁與遷移報告寫「需要告警模式」，**不得顯示成正常但 0 筆**。
- cef_pce 的標頭冒充 PCE（vendor Illumio、product PCE、PCE fqdn／版本）**只用於 audit**；本產品自己產生的事件一律標頭 `Illumio|illumio-ops|<v6 版本>`，不得讓 SOC 把偵測算到 PCE 頭上。
- CEF `rt` 不帶時區（Graylog 7.1 會整行丟棄帶 `+0000` 的 rt，見記憶）；每行帶可 join 的識別（audit：`event_href`；本產品事件：`externalId`＝來源與 id）。
- 送出是 at-least-once：網路送出後、游標寫入前崩潰會重送一批；不得因此漏送。
- 讀批次 → 關閉 flow 連線 → 送出 → 寫游標；不得在網路 I/O 期間持有 FlowDb 連線或寫鎖。游標寫入以讀批次時的 PCE 標記檢查，PCE 切換後舊批次不寫游標。
- 每個 operation 有前端呼叫者，同一 commit；zh 用字過 `test_terminology.py`；兩語系。
- 秘密：`hec_token` 進遮罩清單（目的地是 list，`redact` 要能走 list）；GUI 回填 MASK 時保留原值。
- 新設定段必升 `SCHEMA_VERSION` 9＋`_v8_to_v9`（舊設定檔沒有 `siem` 不得讓服務起不來）。

## Review Focus

1. PCE 切換：flows.sqlite 重建、events／detections id 從 1 重來——游標帶 PCE 標記，不符就從當前 MAX(id) 起算，下一筆新事件照送。
2. 保留清理刪掉游標還沒送到的列（目的地長期不通）——不阻擋清理，記「未送即被清除」筆數並顯示在狀態頁。
3. 單一列每次都送失敗（非 4xx，例如對端看到某內容就斷線）——同一列重試達 max_retries 後進 DLQ、游標前進，不卡死整個目的地；目的地整個連不上則不扣其他列的次數。
4. 新增目的地或為目的地新增來源——游標從當下 MAX(id) 起，不把 90 天歷史灌進 SIEM。
5. 升級客戶的新預設規則（notify=0，只記錄不通知）——SIEM 也不送，與通知通道一致；狀態頁說明。

## Rulings 先定（寫入帳本）

- R1 初始游標＝啟用（或來源加入）當下的 MAX(id)：歷史不送（§7 連續性）。游標列留 `floor_time`（選填，P8 用來接 5.x 已送到的時間），本階段不填。
- R2 detections 只在新建時送一次，帶送出當下的 severity／occurrences／first_seen／last_seen；之後的升級靠告警（P4 的 seen_severity 重發）送達。
- R3 SIEM 尊重 alerts.notify：notify=0（升級後未開通知的新規則、grouped）不送。
- R4 5.x `profile` 欄位不搬：`verify_tls: bool | str`（同 PceSettings）；profile=dev＋tls_verify=False 遷移為 False 並寫報告。
- R5 cef_pce／syslog_cef_pce 可同時勾選 findings／new_connections：那兩種事件用本產品的 ArcSight 方言 CEF（標頭 illumio-ops）。不拒絕。
- R6 DLQ 存完整已格式化內容（不是 512 字預覽），重送不依賴來源列還在；每目的地上限 `dlq_max_per_dest`（預設 10,000），滿了游標停在原地、狀態頁寫「DLQ 已滿」，不丟資料。
- R7 新連線事件只在 `LateralContext.baseline_full` 時記：基準期未滿時「第一次出現」不成立；狀態頁寫「基準期累積中（已 N／需 M 天）」。

### Task 2: 本產品三種事件的格式

- `illumio_ops/siem/records.py`：`SiemRecord{source, kind("audit"|"detection"|"alert"|"new_connection"), record_id, event_time, data}`。
- `formatters` 加 `format_record(rec)`：audit 走既有 `format_event`；其他三種：
  - CEF（cef／syslog_cef，以及 cef_pce 系列的非 audit）：`CEF:0|Illumio|illumio-ops|<版本>|<sig>|<name>|<sev>|…`。sig：`detection.<detector>`、`alert.<rule_type>`、`new_connection.<decision>`；嚴重度 info 1／low 3／medium 5／high 8／critical 10；ext：`rt`（epoch 毫秒，同 ArcSight 方言）、`externalId=<kind>:<id>`、`src`／`dst`／`dpt`／`proto`、`shost`／`dhost`、`cs1=src_labels`、`cs2=dst_labels`（JSON）、`cs3=summary`（detection／alert 的文字，用顯示語言 render）、`cs4=facts`（JSON，截 3,995 字，超過寫 `cs4Truncated=true`），`cat=illumio_ops_<kind>`；新連線另有 `act=<decision>`、`start=first_seen`。
  - JSON（json／syslog_json）：`{"source":"illumio-ops","kind":…,"id":…,"time":ISO8601Z,…}`，省略空值；同上欄位、labels 為物件、facts 原樣。
- 測試：三種事件 × 六種格式的 golden（`tests_v6/siem/test_records_format.py`）；cef_pce 對 alert 標頭是 illumio-ops 不是 PCE；rt 無時區；CEF 跳脫（`=`、`\`、換行）；4,000 字 facts 截斷並標示。

### Task 5: dispatcher 與狀態

- `services/siem/sources.py`：四個讀取器 `read(conn, after_id, limit, dest) -> list[SiemRecord]` 與 `max_id(conn)`：audit（events origin=ingest、可 mask）、alerts（notify=1；app.sqlite；render 用顯示語言；PCE 標記取 alerts.pce_url 是否等於目前 PCE）、detections、new_connections（traffic_pd 過濾）。findings 來源＝alerts＋detections 兩個游標（source 名 `alerts`、`detections`）。
- `services/siem/dispatch.py` `run_siem(ctx, now=None, budget_seconds=None) -> SiemRun`：每個啟用目的地、每個勾選來源：游標不存在或 PCE 標記不符 → 設為 MAX(id)（R1）；讀批（關連線）→ 送出（transport `send_record`，串流型 `finish_batch` 確認）→ 寫游標。暫時錯誤：本批中止、游標停、`head_attempts+1`，達 max_retries 時把該頭列入 DLQ 並前進（Review Focus 3）；永久錯誤（4xx 非 408／429、EMSGSIZE）：該列直接入 DLQ、續送下一列；DLQ 滿：停（R6）。目的地之間獨立（一個卡住不拖累其他）；整輪有時間預算（預設 tick 的 80%）。PCE identity（cef_pce 用）：`/product_version` 每小時最多一次，失敗寫 unknown。
- `services/siem/retention_guard.py`：events／alerts／detections 保留刪除前，計算每個游標落後且將被刪的合格列數，加到 `dropped`（Review Focus 2）。接進 `services/collect/retention.py`、`services/alerts/retention.py`、analysis 保留。
- `services/siem/status.py` `siem_status(ctx) -> SiemStatusView`：每目的地每來源：落後筆數（合格列 id > last_id）、最後送出、最後錯誤、DLQ 筆數、dropped、狀態（ok／behind／failing／dlq_full／needs_alert_mode／baseline_building）。輕量模式下 detections、new_connections 為 needs_alert_mode；alerts 寫「只有事件型告警」。
- `services/siem/tester.py` `test_destination(ctx, dest)`：送一筆測試事件（kind test），不動游標，回傳成功或錯誤字串。
- 排程：`jobs/scheduler.py` 加 `siem_dispatch`（間隔 tick_seconds，instrument 記 job_health）；system 檢查 `siem_backlog`（任一目的地落後 > backlog_warn_rows 或 DLQ 滿 → system 告警）。
- 測試（tests_v6/services/siem/）：初始 MAX(id)；PCE 切換後第一筆新事件照送；backfill 事件不送；notify=0 不送；暫時錯誤不前進且不扣其他列；同一頭列達上限入 DLQ 後下一列送出；4xx 入 DLQ 並續送；DLQ 滿停住；保留清理計入 dropped；送出期間不持有 flow 連線（以 `FlowDb._open` 計數或 monkeypatch 斷言）；時間預算內停止；輕量狀態 needs_alert_mode；traffic_pd 過濾；tester 不動游標。
