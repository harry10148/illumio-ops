## 0. 為什麼重開

3B 交付後使用者回饋：「整體風格介面和呈現方式太工程師」、「investigate 用起來不直覺」、「不需要收件匣與事件調查流程，只要能檢視最近的告警」。原始碼盤點證實 3B 換的是 token 不是骨架：

| 工程師訊號（2026-09-04 盤點） | 數量 |
|---|---|
| 連結文字直接印路由（「Go to #/system/cache」，`withGoto`／`GO_*`） | 37 |
| 等寬字體用於一般文字與數字（`.mono`／`.num`） | 44 |
| 全大寫面板標題（`text-transform: uppercase`） | 19 |
| 畫面印設定檔鍵名（`roField("smtp.password")` 等） | 18 |
| 原始 JSON 區塊（`.codepane`） | 12 |
| 產品內嵌說明文（右欄 guide） | 2 |

決策（使用者 2026-09-04）：
- 體感參考 **PCE 主控台**（左側導覽、清單→詳情、每頁一顆主要動作），借現代 SaaS 的留白與人話；不選 Datadog 式密度。
- **沒有收件匣區、沒有調查流程**：首頁看最近的告警，點一件進去看那一件；調查區回到純工具。
- 視覺 token（Direction D）維持；改的是骨架、頁面型態與文案。

## 1. 資訊架構（取代 v3 §1）

五區不變：首頁／調查／政策／報表／系統。改變的是**殼層**與**調查區的定位**。

```

│ 首頁     ├──────────────────────────────────────────────┤
│ 調查 ▸   │ 內容：清單頁 或 詳情頁（§5.1 只有這兩種）        │
│  告警    │                                              │
│  流量搜尋 │                                              │

│ 報表 ▸   │                                              │

│          │                                              │
│ harry    │                                              │
│ lab-pce  │                                              │
└──────────┴──────────────────────────────────────────────┘
```

- **左側導覽 224px**：五區為一級項，目前區展開子項（子項＝原頂欄各區的 sub-nav）；未處理告警數以小圓標掛在「調查 › 告警」。底部固定使用者＋PCE 環境名＋版本。≤1000px 導覽收成頂列（子項進「更多」）。
- **頂欄取消**；指令面板 ⌘K 改為左導覽底部一列「搜尋或跳轉 ⌘K」；主題／密度／登出進使用者列的彈出選單。
- **健康燈**不再是頂欄元件：首頁右欄「系統健康」卡（六燈＋一句話）承接；其他頁不顯示（沿用「只在首頁」裁決）。
- **調查區＝工具**：告警（清單）、流量搜尋（原流量分析器）、Workload、事件。沒有步進、沒有上下文條。
- 每頁固定「麵包屑 ＋ 標題句 ＋ 副標 ＋ 動作列（至多一顆主要動作）」；標題是**句子**不是名詞（「3 件告警還沒處理」而非「告警」）。

## 3. 告警頁（取代 v3 §3）

一頁就是「那一件事」，敘事順序固定；**沒有**收件匣、步進、上下文條、逐列「看規則」按鈕。

```
麵包屑：首頁 › 告警 › #42（`#/investigate/alerts?id=42`）
標題句：onlineboutique 內 4,662 條連線在 10 分鐘內被擋          [處理中] [標記已處理]
副標：規則「高 Blocked 流量」於今天 13:17 觸發（pd＝potentially blocked，10 分鐘窗）。這些流量目前還是通的：…

發生了什麼      一段話（規則＋主要流向＋規則覆蓋結論）＋三個數字（被擋連線／不同流向／有規則涵蓋）
誰在跟誰講話    表：來源→目的｜服務｜連線｜哪條規則在管（載入時對前 N 條自動問 PCE；ok 允許＋規則集名／crit 沒有規則／neutral 未解析）
                 頁尾：顯示前 N 條，共 M 條 · 「在流量搜尋開啟這個查詢 →」（= 3B 的 ?alert= 入口）
該怎麼辦        2–3 個具體行動列，第一列為建議（左側橘條）：建立排程變更（政策 ruleset，帶 rs/rule）、隔離 <workload>、標記已處理並調整規則
更多（收合）    通知紀錄、規則設定、原始資料下載
右欄            這件事的進度（觸發／已通知／待處理）、受影響的範圍（app／env／workload 數／規則集）、類似的告警（7 天同規則次數、上次處理）
```

- 資料：`GET /api/alerts/<id>`（payload top flows／event matches、dispatch）；「哪條規則在管」＝對 payload 的前 N（預設 8）條 flow 逐條 `POST /api/policy/explain`（§4c），並行、逐列回填，失敗列顯示「PCE 沒回答」不吞錯；事件型告警沒有流量表，改為「發生了什麼」列出 parsed_data 的重點欄位（actor、action、resource）。
- 「發生了什麼」的一段話由模板組成（規則名＋類型＋主要流向＋覆蓋結論），不是自由文案；三個數字直接來自 payload 與 explain 結果。
- 行動：隔離→既有 quarantine API（只在有 workload href 時出現）；排程變更→`#/policy/rulesets?rs=&rule=`（取第一個命中的規則集；沒有命中時改為「建立新規則集」進政策區）；標記已處理→`PATCH`。行動列文案帶對象名（「隔離 loadgenerator」），不用通用動詞。
- 事件／系統型告警同一頁型，只是沒有流量表與隔離行動。

## 5. 視覺系統與頁面規則（取代 v3 §5）

token（色、字、尺度、主題、圖表）沿用 v3 §5 與 3B 已落地的 `tokens.css`，加上 3B Task 7 的 dark `--accent-on` 深墨。以下是**新增**的骨架與文案規則，每條都有守門（§7）。

### 5.1 只有兩種頁型（外加設定頁）

| 頁型 | 結構 | 例 |
|---|---|---|
| 清單頁 | 標題句＋動作列 → 篩選列（分段按鈕＋搜尋） → 列（不是表格欄位牆）：左側嚴重度色條、時間、一句話、對象、狀態晶片；點列進詳情 → 頁尾計數與次要連結 | 告警、報表產出、ruleset、排程 |
| 詳情頁 | 標題句＋動作列 → 敘事區段（h3 人話標題）依「發生什麼 → 證據 → 該怎麼辦 → 更多（收合）」 → 右欄 ≤3 張輔助卡（sticky） | 告警頁、ruleset 詳情、報表產出詳情 |
| 設定頁 | 左：項目清單（名稱＋狀態晶片＋「還缺什麼」一句）；右：一次只編一項，分節（h4＋一句說明｜欄位），底部固定儲存列（「沒有未儲存的變更」／「有 N 項變更」＋還原＋儲存） | 通知通道、SIEM 目的地、PCE 連線、TLS |

面板牆（一頁多個等權重 panel）取消；卡片只用在右欄輔助資訊與首頁背景卡。

### 5.2 文案與識別碼

- **不印路由**：連結文字是動詞或對象名（「看全部」「管理告警規則」「在流量搜尋開啟這個查詢」），`withGoto`／`GO_*` 全部移除。
- **不印設定鍵名**：`smtp.password` 這類 config path 不出現在畫面；密碼欄只顯示「已設定／尚未設定」＋「設定密碼」。
- **不印 JSON**：原始資料改為「下載 JSON」連結或結構化的 key/value；`.codepane` 只留日誌頁與 debug 主控台。
- **等寬字只給識別碼**：IP、port／proto、href、hostname、時間戳；一般數字用 Montserrat tabular（`.num`），一般文字用內文字型。
- **面板標題不全大寫**：h3／h4 用內文字型 15px／14px 粗體；眉標（uppercase＋字距）只留右欄卡片標題與表頭。
- **狀態一律晶片＋文字**（未處理／處理中／已處理；已驗證／未設定），嚴重度用左側色條＋晶片，不靠顏色單獨傳達。
- **說明文出產品**：右欄 guide 移除，改為標題旁「？」開彈出說明（既有 `m-help`）。
- 標題句模板：`{數字} 件{對象}{狀態}`、`{對象} {發生了什麼}`；副標一句話說這頁在做什麼或現況。

### 5.3 設定頁欄位規則

- 欄位標籤用人話（「寄件人」「收件人」「主機與埠」），help 一句放欄位下。
- 秘密欄位：狀態晶片＋「設定／更換」按鈕，永不回顯；長度提示移除。
- 啟用開關在表單頭；「送測試」在表單頭；儲存列固定底部；離開頁面有未儲存變更時 modal 確認（沿用 3B）。
- 通道／目的地清單的「還缺什麼」由後端既有 `missing` 欄位組句。

### 5.4 響應

- ≥1000px：左導覽＋內容；詳情頁右欄 300px。
- <1000px：導覽收頂列、右欄落到內容下方、清單列改兩行。
- 頂列任何情況不得裁字（3B Task 7 教訓）。

## 7. 驗收（補充 v3 §7）

新增守門：

- **文案 lint**（`tests/test_gui_copy_lint.py`）：`areas/`、`components/` 內不得出現 `withGoto(`、`GO_[A-Z_]+ = "#/`、`roField("…"` 帶點號鍵、`class: "codepane"`（白名單：`system.mjs` 日誌頁、`policy_scheduler.mjs` debug 主控台）；i18n 值不得含 `#/` 路由字串（既有 `gui_health_goto` 類鍵刪除）。
- **CSS**：`text-transform: uppercase` 只允許 `.eyebrow`、`th`、`.chip`（白名單測試）；`.mono` 只允許出現在 `data-kind="id"` 的節點（DOM 守門：e2e 掃 `.mono` 節點內容須匹配 IP／port／href／時間戳）。
- **頁型守門**：每條非設定路由的 `data-cov` 頁根必須有 `.phead h2`（標題句）且至多一顆 `.btn.primary`；設定路由必須有 `.savebar`。
- **coverage**：`design/v3/coverage.yaml` 重編：IN-01..06 → AL-01（清單）、AL-02（狀態切換）、AL-03（告警頁）、AL-04（規則判定欄）、AL-05（行動列）；HM-03 移除、OV-02 縮為 HM-04 內一行；新增 SH-01（左導覽）、SH-02（使用者彈出選單）、SH-03（⌘K 入口）。live gate 100%。
- **真機**：以測試機真告警（rule 27）開告警頁、explain 對真 flow；首頁、告警頁、通知通道 1280／800 亮／暗截圖親看；CLAUDE.md 報表規則不適用本階段。

## 8. 分階段（取代 v3 §8 的第 3–4 步）

3B 之後、3C 之前，新增子計畫 **3E 工作台**（`docs/superpowers/plans/2026-09-04-phase3e-workbench.md`，輪到才寫），任務順序：

1. 殼層：左導覽、頁首（麵包屑／標題句／動作列）、使用者彈出選單、⌘K 入口；健康燈改首頁卡；響應規則。
2. 頁型元件：`listPage`／`detailPage`／`settingsPage` 三個骨架＋列元件（色條／時間／一句話／對象／晶片）＋儲存列；文案 lint 與頁型守門先紅。
3. 告警：清單頁、告警頁（自動 explain、行動列、右欄）；移除 3B 步進／上下文條／逐列看規則；路由轉址；coverage 重編。
4. 首頁：最近的告警＋三張背景卡；移除 HM-03／posture 卡。
5. 系統區：十頁改設定頁型（先通道、SIEM、PCE，其餘依同模板）；鍵名／JSON 清除。
6. 政策與報表：清單→詳情頁型套用；`withGoto` 全清；右欄 guide 移除。
7. 登入頁對齊（左導覽不出現）、CHANGELOG、docs（gui-tour 依新殼層）。

每任務獨立 commit、CI 綠、部署測試機；3C（報表／CLI）與 3D（收尾、版本號）順延。
